# 実機手動テストチェックリスト（Waveshare RP2350-Touch-LCD-2.8 想定）

ホスト単体テストではカバーできない、USB・液晶・SD・タッチ・音声などの確認用です。リリース前やハード変更後に実施することを推奨します。

**準備:** `pico_basic.uf2` を書き込み済みのボード、データ対応 USB ケーブル、シリアルターミナル（VS Code Pico Serial Monitor や `screen` / `minicom` 等）。

| # | 確認内容 | 手順 | 期待結果 | 合否 |
|:-:|:---|:---|:---|:---:|
| G1 | 取り込みと描画 | `10 DIM A(1000)` / `20 CIRCLE (40,40),12,14` / `30 GET@ (28,28)-(52,52), A` / `40 PUT@ (200,150), A` → `RUN` | 右下に同じ円が複写される | [x] |
| G2 | 配列不足の検出 | `10 DIM B(10)` / `20 GET@ (0,0)-(60,60), B` → `RUN` | `Array too small for image` が表示され、ハングしない | [x] |
| G3 | 画像サイズの上限 | `DIM C(1500)` → `GET@ (0,0)-(60,60), C` | `Array too small for image` が出る（60×60=3600 画素は入らない） | [x] |
| G4 | 繰り返し実行 | G1 のプログラムを `RUN` → もう一度 `RUN` | 2 回目も同じ結果。`Out of Memory: Array Heap Full` が出ない | [x] |
| G5 | 再 DIM の拒否 | `DIM D(10)` → もう一度 `DIM D(10)` | `Duplicate definition` が表示される（`CLEAR` か `RUN` でやり直せる） | [x] |
| G6 | PUT@ XOR で消去 | `10 CLS` / `20 DIM A(500)` / `30 CIRCLE (10,10),8,15` / `40 GET@ (0,0)-(20,20),A` / `50 PUT@ (150,100),A,3` / `60 WAIT 1000` / `70 PUT@ (150,100),A,3` → `RUN` | 中央に円が1秒出て消える。**左上の円は残ったまま**（XOR で 2 回置くと消える） | [x] |
| G7 | PUT@ 拡大 | G6 に続けて `PUT@ (100,100)-(180,180), A` | 左上の小さな円が大きく引き伸ばされて中央付近に描かれる | [x] |
| G8 | PUT@ 論理演算 | `10 CLS` / `20 LINE (100,100)-(180,140),12,BF` の上に、G6 の A を `PUT@ (120,110), A, 1`（OR）や `, 2`（AND）で描く | 背景の矩形と重なった結果になる（単純上書きではない） | [x] |

> **`RUN` は画面をクリアしません**（変数・配列は初期化されます）。グラフィックのプログラムは先頭に `CLS` を入れると、前の表示と重ならず分かりやすくなります。

> **取り込める画像の大きさ:** 配列ヒープは 12,288 バイト（1,536 要素）で、`GET@` は先頭 2 要素を幅・高さに使います。
> つまり **最大 1,534 画素（正方形なら 39×39 程度）** までです。それを超える `DIM` は `Out of Memory: Array Heap Full`、
> 配列が小さすぎる `GET@` は `Array too small for image` になります。
>
> **必要な配列サイズ:** `GET@ (0,0)-(N,N)` は `(N+1)×(N+1)` 画素。`DIM A(M)` は `M+1` 要素なので、
> **`M+1 ≥ (N+1)×(N+1) + 2`** を満たすこと（幅・高さで 2 要素消費）。
> 例: `GET@ (0,0)-(20,20)` は 21×21=441 画素 → 443 要素必要 → `DIM A(442)` 以上。

> 電圧は `BAT_ADC`（GPIO27 / ADC1）を **200K:100K で分圧**した値を 3 倍して求めています（回路図より）。
> テスターの実測と大きくずれる場合は `src/hal_battery.cpp` の `BAT_DIVIDER` / `ADC_VREF` を調整してください。
> 同じ回路にある **BAT_EN（GPIO26）は電源ラッチの制御線**です。触ると電源が切れる可能性があるため、本実装では一切操作していません。

## J. GPIO 入力・アナログ入力・内蔵温度（`PIN` / `ADIN` / `CPUTEMP`）

拡張コネクタの **GPIO28 / GPIO29** を使います。配線が要る項目は、結線してから確認してください。

| # | 確認内容 | 手順 | 期待結果 | 合否 |
|:-:|:---|:---|:---|:---:|
| J1 | 内蔵温度（配線不要） | `PRINT CPUTEMP` | 20〜50 くらいの値（実測 **35.9**） | [x] |
| J10 | 温度の分解能と追従（配線不要） | `10 PRINT CPUTEMP : WAIT 1000 : GOTO 10` を回し、途中で基板の裏に息を吹きかける | 値が 0.4683℃ 刻み（2 値の往復）ではなく細かく動く。息を当てると下がり、やめると戻る（実測: 最小変化 **0.0036℃**、1 LSB の約 1/130。36.55→37.41→37.16 と滑らかに推移） | [x] |
| J2 | アナログ入力（配線不要） | `PRINT ADIN(28)` | 0〜4095 の範囲の値が返る。開放ピンなので値は不定（実測 **759**） | [x] |
| J3 | アナログ入力の両端 | GPIO28 を GND に落として `PRINT ADIN(28)`、次に 3V3 に繋いで同じ | GND で 0 付近、3V3 で 4090 前後 | [ ] |
| J4 | 可変抵抗 | 半固定抵抗を 3V3–GPIO28–GND で繋ぎ、回しながら `10 PRINT ADIN(28) : GOTO 10` | 0〜4095 の間で滑らかに変化する | [ ] |
| J5 | BAT_EN の保護 | `PRINT ADIN(26)` | **エラーになり、電源は落ちない**（`GPIO26 is BAT_EN ...`） | [x] |
| J6 | 電池ピンの読み出し（配線不要） | `PRINT ADIN(27)*3300/4095*3` と `PRINT BATTERY(0)` | 両者がおおむね一致する（実測 **4194.51** / **4197**、差 0.06%） | [x] |
| J7 | 内蔵プルアップ（配線不要） | `GPIO 28, 0, 0, 1` → `PRINT PIN(28)` | `1`（実測 **1**） | [x] |
| J8 | 出力→入力の折り返し（配線不要） | `GPIO 28, 1, 1` → `PRINT PIN(28)`、続けて `GPIO 28, 1, 0` → `PRINT PIN(28)` | `1` → `0`（実測 **1** → **0**）。出力した値をパッドから読み戻せる（`hal_gpio_write` と `hal_gpio_read` の同時確認） | [x] |
| J11 | 内蔵プルダウン（配線不要／**RP2350-E9 回避策の確認**） | `GPIO 28, 0, 0, 2 : PRINT PIN(28)`（**設定と読み取りで同じ 28 を指定すること**） | `0`（実測 **0**）。同じコマンドが回避策の前は `1` を返していた（下の注記を参照） | [x] |
| J9 | スイッチ読み取り | タクトスイッチを GPIO28–GND に入れ、`GPIO 28, 0, 0, 1` のうえで `10 IF PIN(28)=0 THEN PRINT "PUSH"` `20 GOTO 10` | 押している間だけ表示が流れる | [ ] |

> **GPIO26（BAT_EN）には触らないでください。** 電源ラッチの制御線で、アナログ入力に切り替えると電源が落ちる可能性があります。`ADIN(26)` はソフト側で拒否しています（J5）。
> `ADIN` は 16 サンプルの平均を返します。LCD の SPI 転送のノイズを均すためで、`hal_battery` と同じ方針です。
> `CPUTEMP` は**チップの温度**であって室温ではありません。また未校正なので数℃の個体差があります。
> ADC の 1 LSB は約 **0.47℃** もあるため、温度だけ 256 サンプルの平均を**小数のまま**使って分解能を稼いでいます。
> 値が 0.4683℃ 刻みでしか動かない場合、平均が整数に丸められている（オーバーサンプリングが効いていない）疑いがあります。
> **`GPIO` 文で触ってよいのは GPIO28 / GPIO29 だけ**です。他は基板上で使用済みで、特に **GP19-24 は MicroSD（GP20 は SD_CMD）**、**GP6/GP7 はタッチ・IMU・RTC の I2C**、**GP26 は BAT_EN** です。誤って設定するとその機能が止まります。
> `CPUTEMP` の温度は指の表面（約 33℃）より高いことが多いため、**温めるより息を吹きかけて冷やすほうが変化を確認しやすい**です。
> **配線が要るのは J3・J4・J9 だけ**です。J7・J8・J11 は内蔵プルと出力の折り返しを使うので、何も繋がずに `PIN()` を確認できます。
>
> **RP2350-E9（プルダウンのラッチアップ）について:** RP2350 には、入力に設定して内蔵プルダウンを有効にしたパッドが、リーク電流（最大 120uA）でおよそ 2.1〜2.2V に張り付き、**開放でも `1` と読めてしまう**シリコン不具合があります。プルアップ側は影響を受けません。
> `hal_gpio_read()` にデータシートの回避策（読む直前だけ入力バッファを有効にする）を入れてあります。J11 はその確認項目です。
> **実用上は「プルアップ＋スイッチを GND へ」の配線を推奨**します。この erratum の影響を受けず、BASIC 側も `IF PIN(n)=0 THEN` と自然に書けます。

## K. IMU（`ACCEL` / `GYRO` / `IMU`）

QMI8658（6軸）。配線は不要で、**基板を傾けるだけ**で確認できます。

| # | 確認内容 | 手順 | 期待結果 | 合否 |
|:-:|:---|:---|:---|:---:|
| K1 | 認識 | 起動時のシリアル出力 | `[IMU] QMI8658 at 0x6B` が出る（`not found` にならない） | [x] |
| K2 | 状態表示 | 基板を水平に置いて `IMU` | 6 個の数値が 2 行で出る。`IMU NOT FOUND` にならない | [x] |
| K3 | 重力（水平） | 画面を上にして水平に置き `IMU` | **Z 軸が -1006**（重力 1G）、X/Y は 32/24 と 0 付近 | [x] |
| K4 | 重力（裏返し） | 上下をひっくり返して `IMU` | **Z 軸が +994** と符号が反転する | [x] |
| K5 | 軸の割り出し | 水平から、左端を持ち上げる／手前を持ち上げる | 左端を上げると **X が負**（実測 -425）、手前を上げると **Y が正**（実測 +630） | [x] |
| K6 | 静止時のゼロ点 | 水平に置いたまま `10 PRINT ACCEL(0) : WAIT 500 : GOTO 10` | 値がおおむね一定（実測 37〜39、**ばらつき ±1 mG**。オフセット約 38 mG は K5 と一致） | [x] |
| K7 | ジャイロ静止 | 動かさずに `PRINT GYRO(0); GYRO(1); GYRO(2)` | すべて 0 付近（実測 -1 / 3〜4 / 0 dps） | [x] |
| K8 | ジャイロ回転 | くるっと回しながら `10 PRINT GYRO(2) : GOTO 10` | 回している間だけ大きな値が出て、止めると 0 に戻る（実測 最大 **-349 dps**、静止で **0**） | [x] |
| K9 | 3 軸の同時性 | `10 PRINT ACCEL(0); ACCEL(1); ACCEL(2) : GOTO 10` を回しながらゆっくり傾ける | 3 つの値が滑らかに連動して変わる（実測: 17°→61° の傾斜で 1 サンプルあたり最大 55 mG、**飛びなし**） | [x] |
| K10 | サンプル | `LOAD "TILT.BAS"` → `RUN`（**水平に置いてから**。最初にゼロ点を取る） | 傾けた方向にボールが転がり、壁で跳ね返る（K5 の符号反転が正しいことの確認） | [x] |
| K11 | タッチとの共存 | `IMU` の直後に画面をなぞって `draw.bas` を動かす | どちらも正常。同じ i2c1 バスだが競合しない | [x] |

> **軸の向き（すべて実測）:** 画面を上にして水平で **Z = -1000 前後**（裏返すと +1000）。
> 左端を持ち上げる（＝右が下がる＝ボールは右へ転がる）と **X が負**、手前を持ち上げる（＝奥が下がる＝ボールは奥へ転がる）と **Y が正**。
> つまり**画面座標とは両軸とも符号が逆**です。ゲームでは `-ACCEL(0)` / `-ACCEL(1)` を使ってください（`samples/tilt.bas` 参照）。
> 水平に置いても **X/Y に 50 前後のオフセット**が乗ります。置き方や基板の傾きによるので、起動時に静止値を読んでゼロ点にするのが確実です。
> フルスケールは **加速度 ±4g / ジャイロ ±512dps**、ODR は 250Hz です（`src/hal_imu.cpp`）。手で回した実測が -349 dps だったので余裕はありますが、勢いよく振ると頭打ちになります。
> I2C は **タッチ(0x1A)・RTC(0x51)・IMU(0x6B)** が同じ i2c1 を共有します。アドレスが違うので競合しません（K11）。
> **IMU のアドレスは実機のバス走査で 0x6B と判明しました**（回路図では SDO/SA0 が GND に見え 0x6A を想定していた）。初期化で 0x6A→0x6B の順に試すので、どちらの基板でも動きます。
> 見つからないときは `IMU` と打つと、WHO_AM_I の生値と i2c1 に応答したアドレスの一覧が出ます。
> **感度の個体差:** 静止時の合成ベクトル √(X²+Y²+Z²) は 1000 mG になるはずですが、実測は平均 **1049 mG**（約 5% 高め）でした。データシートの `Initial Sensitivity Tolerance ±6 %（Board Level）` の範囲内で、無校正なら想定どおりです。ゲームには影響しませんが、傾斜角を正確に求めるなら校正が必要です。
